# 平台守门人整改报告

统一平台重大事项、整改承诺、验证证据和监管报告，解决各团队分别报送、
同一事件难以并案核对的问题。

## 业务事实

- 监管将综合运用标准、价格执法和质量监管整治内卷式竞争
- 平台企业需要承担数据、算法、流量和规则管理责任
- 垄断风险监测与经营者集中审查需要技术支撑

## 协作角色

- 市场监管人员：查阅监管摘要、逐条比对平台承诺与实际完成
- 平台企业：分级报送、封存事实、分派整改、作出承诺、提交证据
- 经营商家：受影响主体，通过申诉与补救通道参与
- 案件审查人员：调阅受控附件、复核复发关联与关闭结论
- 自动监测系统：**只能提出线索，无权定级、立案、归并、关联复发或关闭事件**

## 服务能力

核心实现见 `src/reporting.py`，仅依赖 Python 3.11 标准库。

1. **分级报送**：重大（1 日内）/ 较大（3 日内）/ 一般（7 日内），
   按首次发现时间计算报送时限并标记按时或迟报，报送后分级不可更改。
2. **线索边界**：自动监测只产生线索（signal）；线索转报必须经团队责任人
   人工确认；误报线索由人工排除并留理由。立案必须至少归并一条人工上报。
3. **跨团队归并**：系统依据共同线索或时间窗内共同标签给出归并候选
   （仅建议），由合规负责人确认；商家申诉、价格补贴、流量分发等不同团队
   的上报归并到同一事件，报送后仍可追加归并。
4. **事实封存**：事件发生后冻结影响时间窗、规则版本、受影响主体与临时措施；
   封存不可重复执行，修正只能追加，原值保留在修正留痕中（分级等字段不可借修正改写）。
5. **整改分派**：根因调查、用户补救、制度修订、复测验证四类任务各分派一次，
   经"提交结果（附批准证据）→ 合规复核办结"闭环；复测必须明确通过/不通过，
   失败可重新打开任务并阻止事件关闭。
6. **整改承诺与期限提醒**：承诺作出后表述不可改写；系统按责任期限输出
   逾期与临期提醒。
7. **证据审签**：双人双签（两名不同审批人）、上传与审签职责分离；
   被否决证据不能随整改结果提交。商业秘密仅作为受控附件登记编号、
   受控位置与哈希，正文不入样例、不进监管摘要。
8. **复发关联**：只能与已关闭历史事件、且规则模块重合的事件由人工确认关联，
   记录版本变化与理由；自动监测的"疑似事件"仅作参考。
9. **监管摘要**：封存事实、归并上报、任务、承诺对照、证据、复发、提醒与
   未解决风险一次生成；未解决风险与摘要结论共用同一口径，结论不得与风险矛盾，
   不得淡化（仍有风险时明确"不得作为整改完成依据"）。
10. **关闭闸门**：封存齐备、四类任务办结且复测通过、承诺全部验证兑现、
    无在审/被引用的否决证据、未解决风险清零，方可由责任人关闭。
11. **承诺对账**：监管人员可通过 `compare_commitments` 逐条查看承诺事项、
    期限、验证状态、佐证证据与对账结论（已兑现 / 逾期兑现 / 逾期未兑现 /
    验证未通过 / 待验证）。

## 目录说明

- `contracts/domain.schema.json`：基础共享资料的字段与约束。
- `contracts/case.schema.json`：整改报告服务样例（事件 / 上报 / 线索）契约。
- `fixtures/context.json`：不含真实个人信息的公开基础样例。
- `fixtures/build_case_sample.py`：可复现构建完整业务场景样例。
- `fixtures/case_sample.json`：算法回滚跨商家申诉、价格补贴、流量歧视
  三团队并案的完整服务状态（另含一个 3 月已关闭历史事件用于复发关联）。
- `fixtures/regulatory_summary.sample.json`：上述事件的监管摘要样例，
  含承诺兑现对照与未淡化的未解决风险。
- `src/records.py`：基础资料读取与校验。
- `src/reporting.py`：统一重大事项与整改报告服务。

样例中不包含账号、密钥、连接凭据或可识别个人；商家清册等商业秘密仅以
受控附件形式登记，凭受控通道单独调阅。

## 本地检查

```bash
python fixtures/build_case_sample.py   # 重新生成服务与监管摘要样例
python -m unittest discover -s tests   # 运行全部测试
```

测试可确认：自动监测无法越权定级立案、跨团队上报归并一致、封存修正留痕、
证据双人双签与职责分离、逾期承诺在摘要中如实列示、风险未清零时关闭被拒绝，
以及监管承诺对账结论与实际完成情况相符。
